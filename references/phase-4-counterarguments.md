# Phase 4: Counterarguments

Load this file only after the user approves the phase 1 research brief and asks to continue.

Do not use this file during phase 1.

## Goal

Pressure-test the current framing and emerging conclusions.

This phase is about challenging the working view, not defending it.

## Preconditions

Only proceed if the user already approved:

- a clear research question
- explicit boundaries
- a usable framework
- an evidence base or evidence ledger strong enough to challenge

If there is no real evidence base yet, return to phase 3 instead of inventing abstract objections.

## What This Phase Should Produce

Produce a pressure-test record that makes weaknesses visible:

- what the current working view appears to be
- what the strongest opposing interpretations are
- what assumptions are most fragile
- what evidence, events, or conditions would invalidate the current view
- what historical or present-day counterexamples matter most

Do not collapse this phase into final synthesis or scenario analysis.

## Workflow

Run these steps in order:

1. Restate the approved research question.
2. Restate the current working view, framing, or emerging conclusion being tested.
3. Identify the strongest competing interpretations or opposing claims.
4. List the assumptions that the current view depends on.
5. Mark which assumptions are:
   - central
   - uncertain
   - weakly supported
6. Identify failure cases and invalidation conditions:
   - what evidence would seriously weaken the current view
   - what evidence would directly refute it
   - what real-world developments would change the conclusion
7. Find the most relevant historical or present-day counterexamples.
8. Distinguish between:
   - true contradictions
   - partial exceptions
   - edge cases that do not materially change the main view
9. Summarize what remains robust and what now looks fragile.
10. Stop and wait for user confirmation before moving into scenario analysis or synthesis.

## Output Shape

Use this compact backbone:

- `Approved Research Question`
- `Current Working View`
- `Strongest Counterarguments`
- `Fragile Assumptions`
- `Invalidation Conditions`
- `Counterexamples`
- `What Still Holds / What Weakens`
- `Stop / Continue`

Add these sections only when useful:

- `Alternative Interpretation`
- `Most Dangerous Unknown`
- `Evidence Needed To Resolve The Dispute`

## Pressure-Test Standards

Prefer the strongest challenge, not the easiest challenge.

Good counterargument work:

- attacks central assumptions rather than surface wording
- uses evidence or plausible mechanisms
- separates serious objections from cosmetic disagreement
- identifies what would actually change the judgment

Weak counterargument work:

- produces straw-man objections
- lists many tiny objections instead of a few decisive ones
- treats all exceptions as fatal
- collapses into debate without a clear invalidation standard

## Quality Bar

The value of this phase is intellectual honesty.

Prefer:

- direct confrontation with the best opposing case
- explicit invalidation conditions
- a short list of high-value weaknesses
- clear separation between major risk and minor caveat

Avoid:

- defending the current view by default
- writing a final verdict here
- repeating the evidence ledger without pressure-testing it
- using generic objections that would apply to any topic

## Stop Rule

After producing the pressure-test record, stop.

Do not automatically proceed into:

- scenario analysis
- final synthesis
- final recommendation

Allow at most a one-line next step, such as:

`Next step: build scenarios around the two most serious invalidation conditions.`
