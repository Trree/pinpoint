# Phase 2: Framework Building

Load this file only after the user approves the phase 1 research brief and asks to continue.

Do not use this file during phase 1.

## Goal

Turn the approved research question into a usable research framework.

This phase is still about structure, not evidence collection.

## Preconditions

Only proceed if phase 1 already produced and the user already approved:

- a clear research question
- explicit boundaries
- a usable research brief or equivalent phase-1 output

If any of those are missing, return to phase 1 instead of improvising.

## What This Phase Should Produce

Produce a framework that makes the next research step obvious:

- what subquestions need to be answered
- what variables or actors matter most
- what organizing lens best fits the problem
- what kind of evidence would later be needed
- what should be researched first

Do not gather evidence yet.

## Workflow

Run these steps in order:

1. Restate the approved research question.
2. Restate the approved boundaries.
3. Choose the primary organizing lens that best fits the question:
   - `Structure`
   - `Mechanism`
   - `Comparison`
   - `Timeline`
   - `Actors`
4. Explain in one or two lines why that lens fits.
5. Break the question into 3-6 subquestions.
6. Identify the key variables, forces, or actors that recur across the subquestions.
7. For each subquestion, specify the kind of evidence that would later be needed:
   - data
   - case studies
   - historical analogies
   - expert views
   - policy or legal material
   - technical documentation
8. Sequence the subquestions in a useful research order.
9. Stop and wait for user confirmation before moving to evidence gathering.

## Output Shape

Use this compact backbone:

- `Approved Research Question`
- `Boundaries`
- `Framework Lens`
- `Core Subquestions`
- `Key Variables / Actors`
- `Evidence Types Needed`
- `Research Order`
- `Stop / Continue`

Add these sections only when useful:

- `Why This Lens Fits`
- `Critical Unknowns`
- `Most Decision-Relevant Subquestion`

## Quality Bar

The framework should help the next research phase, not inflate it.

Prefer:

- subquestions that are distinct but connected
- variables that clearly affect the answer
- an organizing lens that matches the problem type
- evidence categories instead of source lists
- a research order that reduces confusion early

Avoid:

- turning subquestions into full answers
- collecting or citing sources in this phase
- generating too many branches
- repeating the same question in slightly different wording
- building a framework that ignores the approved boundaries

## Stop Rule

After producing the framework, stop.

Do not automatically proceed into:

- web search
- source collection
- argument synthesis
- counterarguments
- scenario analysis

Allow at most a one-line suggestion for the next step, such as:

`Next step: gather evidence for the first two subquestions.`
