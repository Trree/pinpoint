# Phase 3: Evidence Gathering

Load this file only after the user approves the phase 1 research brief and asks to continue.

Do not use this file during phase 1.

## Goal

Gather evidence against the approved question and framework.

This phase is about building an evidence base, not producing a final synthesis.

## Preconditions

Only proceed if the user already approved:

- a clear research question
- explicit boundaries
- a usable framework, or at minimum a clear set of subquestions

If the framework is missing, return to phase 2 instead of gathering evidence in a scattered way.

## What This Phase Should Produce

Produce an evidence ledger that makes later synthesis easier:

- what claims or subquestions each source informs
- what type of evidence each item provides
- how strong or weak each item appears
- where evidence is missing, contradictory, or stale
- what should be investigated next

Do not turn the evidence ledger into a full argument yet.

## Workflow

Run these steps in order:

1. Restate the approved research question.
2. Restate the relevant subquestions or claims that need evidence.
3. For each subquestion, state what kind of evidence is most useful.
4. Gather evidence in a way that keeps facts and inferences separate.
5. For each evidence item, record:
   - what it says
   - which subquestion it informs
   - what type of evidence it is
   - how current it is
   - how reliable it appears
6. Group evidence by subquestion or claim, not by source alone.
7. Mark where evidence is:
   - strong
   - mixed
   - weak
   - missing
8. Note contradictions without resolving them too early.
9. Highlight the most decision-relevant gaps.
10. Stop and wait for user confirmation before moving into synthesis or counterarguments.

## Evidence Priorities

Prefer stronger evidence before weaker evidence.

General priority order:

1. primary data or original documents
2. official disclosures, technical docs, filings, or policy texts
3. strong secondary analysis with transparent sourcing
4. expert commentary
5. anecdotal or weakly sourced claims

When working with evidence:

- treat recency as important when the topic is fast-moving
- prefer direct evidence over repeated summaries
- distinguish observation from interpretation
- say when the evidence quality is uncertain

## Output Shape

Use this compact backbone:

- `Approved Research Question`
- `Subquestions / Claims To Support`
- `Evidence Ledger`
- `Evidence Strength`
- `Conflicts And Gaps`
- `Stop / Continue`

Add these sections only when useful:

- `Source Priority Notes`
- `Most Decision-Relevant Evidence`
- `Most Important Missing Evidence`

## Evidence Ledger Format

Keep the ledger concise and structured. For each item, capture:

- source or document
- relevant claim or subquestion
- evidence type
- short factual takeaway
- reliability note
- recency note

If useful, use a table. If not, use short bullets.

## Quality Bar

The value of this phase comes from disciplined separation:

- fact vs inference
- strong evidence vs weak evidence
- current evidence vs stale evidence
- direct support vs indirect context

Prefer:

- evidence grouped by the question it answers
- short summaries of what each item actually establishes
- explicit notes when evidence is incomplete
- transparent uncertainty

Avoid:

- writing a conclusion before enough evidence exists
- treating all sources as equally strong
- burying contradictions
- letting source summaries replace question-driven evidence tracking
- generating a source dump with no structure

## Stop Rule

After producing the evidence ledger, stop.

Do not automatically proceed into:

- synthesis
- final judgment
- counterarguments
- scenario analysis

Allow at most a one-line next step, such as:

`Next step: synthesize the strongest and weakest evidence for the top two subquestions.`
